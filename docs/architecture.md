## Компоненты

### Chat API (модульный монолит)

Единый Go-процесс, содержащий:

- **users** — регистрация, аутентификация, контакты
- **e2e** — prekeys, хранение и маршрутизация ciphertext
- **gateway** — единая точка входа gRPC для клиента
- **chats** — логика 1:1-чатов, статусы, presence, typing

БД: PostgreSQL (`postgres-chat`).

### Центр Безопасности (отдельный бинарник)

Автономный Go-процесс:

- Принимает события от Chat API
- Строит граф связей между аккаунтами
- Хранит данные в **собственной** PostgreSQL (`postgres-security`)
- Отдаёт Admin API для интерфейса администратора

**Принцип:** Центр Безопасности собирает данные о связях и не должен находиться в одном бинарнике с чат-приложением. Если Chat API падает, Центр продолжает работать (и наоборот — чаты работают без Центра).

### Desktop (Wails)

- **React** — UI
- **Go (internal)** — E2E crypto, device fingerprint, gRPC-клиент к Chat API
- Локальный поиск по чатам — индекс на клиенте

### Shared

- `shared/proto` — protobuf-контракты (события, gRPC-сервисы, DTO)
- `shared/` — общие Go-модели при необходимости

## Стек

| Слой | Технология |
|------|------------|
| Backend | Go 1.22+ |
| Клиент | Wails v2 + React |
| БД | PostgreSQL (две инстанции: чаты и безопасность) |
| Транспорт | gRPC + protobuf |
| Ops | HTTP `GET /health` для локальной проверки и healthcheck |
| Кэш/очередь | Outbox в PostgreSQL; Redis — возможный следующий этап |

## Границы доверия (trust boundaries)

| Данные | Клиент | Chat API | Центр Безопасности |
|--------|--------|----------|-------------------|
| Private keys | ✅ | ❌ | ❌ |
| Plaintext сообщений | ✅ | ❌ | ❌ |
| Ciphertext | ✅ (кэш) | ✅ (хранение) | ❌ |
| Public prekeys | ✅ | ✅ | ❌ |
| Метаданные сообщений (from/to/time) | ✅ | ✅ | ✅ (события) |
| Device fingerprint (сырые сигналы) | ✅ | ❌ | ❌ |
| device_hash | — | ✅ (в событиях) | ✅ |
| Граф связей аккаунтов | ❌ | ❌ | ✅ |

## Безопасность канала и учётных данных

- Локальная среда разработки использует plaintext gRPC (`localhost`).
- Для production нужен TLS 1.3 / mTLS между сервисами.
- Пароли не используются: вход построен на **Ed25519 challenge-response**.
- E2E v0 использует X25519 + HKDF-SHA256 + AES-256-GCM; целевая схема — Double Ratchet.
