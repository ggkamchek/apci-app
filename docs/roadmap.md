# Roadmap продукта APCI

Документ описывает видение платформы, текущее состояние кода и план развития.  
Это **продуктовый** roadmap, а не учебное ограничение scope.

---

## Видение

**APCI** — десктопная коммуникационная платформа с архитектурной приватностью: сервер не имеет доступа к содержимому переписки, а анализ рисков (мультиаккаунтинг) вынесен в отдельный Центр Безопасности.

Полное видение возможностей — в [overview.md](./overview.md).

## Текущее состояние (v0)

Что уже работает локально через `.\scripts\dev.ps1`:

| Область | Статус | Примечание |
|---------|--------|------------|
| Регистрация и вход | ✅ | gRPC, desktop UI |
| Device fingerprint | ✅ | `device_hash` на клиенте |
| Центр Безопасности | ✅ | Отдельный сервис + админка |
| Ingest `user.registered` / `user.logged_in` | ✅ | Chat API → Security Center |
| Граф `same_device` | ✅ | Клоны на одном устройстве |
| Admin UI | ✅ | Обзор, Устройства, Связи, Расследование, Сравнение |
| E2E (базовый) | ✅ | Prekeys, отправка/инбокс ciphertext |
| Контакты, 1:1 чат (полный UX) | 🔄 | Частично, в разработке |
| Ingest `contact.added`, `message.sent` | 📋 | Контракт есть, публикация — в планах |
| Группы, каналы, голос, экономика | 📋 | Roadmap |

Условные обозначения: ✅ готово · 🔄 в работе · 📋 запланировано

## Этап 1 — Базовый мессенджер

Цель: полноценный 1:1 мессенджер с E2E и минимально необходимой инфраструктурой.

### Chat API + Desktop

| Функция | Статус |
|---------|--------|
| Регистрация и вход | ✅ |
| Список контактов | 🔄 |
| Чат 1-на-1 с E2E | 🔄 |
| Статусы сообщений (sent / delivered / read) | 📋 |
| Presence (в сети / не в сети) | 📋 |
| Индикатор набора | 📋 |
| Локальный поиск по чатам | 📋 |

### Центр Безопасности

| Функция | Статус |
|---------|--------|
| Ingest регистрации и входа | ✅ |
| Связь `same_device` | ✅ |
| Админка: обзор, устройства, связи, расследование | ✅ |
| Ingest контактов и сообщений | 📋 |
| Связи `shared_contact`, `communicates_with` | 📋 (логика готова, нужны события) |
| Outbox / retry при недоступности Центра | 📋 |

### Принцип этапа 1

> Сначала стабильный продукт для общения и наблюдаемость связей между аккаунтами. Автоматические санкции — не на этом этапе.

## Этап 2 — Политики и enforcement

| Функция | Описание |
|---------|----------|
| Кластеризация связанных аккаунтов | Группы «подозрительных» клонов |
| Пороговые правила | По весам рёбер графа |
| Ограничение регистрации | В перегруженном кластере |
| Risk score (прозрачный для админа) | Не скрытый blacklist |
| Outbox событий | Гарантированная доставка в Центр |

Политика платформы: **один человек — один аккаунт**. На этапе 1 она только визуализируется; на этапе 2 — применяется.

## Инфраструктура

| Компонент | Назначение |
|-----------|------------|
| `server/` | Chat API (users, e2e, gateway, chats) |
| `security-center/` | Граф связей, ingest, admin API |
| `desktop/` | Wails-клиент, crypto, fingerprint |
| `shared/proto/` | gRPC-контракты между сервисами |

---

## События ingest (контракт)

| Событие | Когда | Данные | Публикация из Chat API |
|---------|-------|--------|------------------------|
| `user.registered` | После регистрации | `user_id`, `device_hash` | ✅ |
| `user.logged_in` | После входа | `user_id`, `device_hash` | ✅ |
| `contact.added` | После добавления контакта | `user_id`, `contact_id` | 📋 |
| `message.sent` | После сохранения ciphertext | `from`, `to`, `message_id` | 📋 |

**Не передаётся:** plaintext, ciphertext, private keys.

---

## Вне scope (намеренно)

- Хранение private keys на сервере
- Серверный поиск по содержимому сообщений
- Скрытый risk score без доступа администратора
- Смешивание БД чатов и графа безопасности в одном процессе
