# Центр Безопасности

**Владелец:** Sudeeneess  
**Путь:** `security-center/` (отдельный бинарник)  
**Desktop (fingerprint):** `desktop/internal/fingerprint`

---

## Назначение

Обеспечить основу для выявления **мультиаккаунтинга** — ситуации, когда один человек владеет несколькими аккаунтами.

### Подход в MVP

Не банить и не скорить. **Собирать связи** между аккаунтами и показывать их администратору. На основе накопленных данных в фазе 2 вводятся правила и enforcement.

---

## Архитектурная позиция

- Отдельный бинарник, **не** часть Chat API.
- Собственная PostgreSQL.
- Автономен: продолжает работу при падении чатов.
- Chat API не зависит от Центра: при недоступности Центра пользователи продолжают общаться.

Подробности интеграции — [integration.md](../integration.md).

---

## MVP scope

### Делает

- Принимает события: `user.registered`, `user.logged_in`, `contact.added`, `message.sent`
- Строит рёбра графа: `same_device`, `shared_contact`, `communicates_with`
- Сохраняет связи в БД
- Отдаёт Admin API: таблица A — B — тип — вес — дата

### Не делает

- Скрытый risk score
- Автоматические баны
- Блокировка регистрации
- Детектирование паттернов абуза
- Анализ стиля письма
- Анализ содержимого сообщений
- Учёт presence / typing / локального поиска

## Device fingerprint

### Где считается

На **клиенте** (desktop). На сервер уходит только `device_hash`.

### Сигналы (мягкий fingerprint)

| Сигнал | Примечание |
|--------|------------|
| OS + версия | |
| CPU model, core count | Без serial number |
| RAM (округлённо) | |
| Screen resolution + DPI | |
| Timezone / locale | |
| Installation ID | UUID при первой установке |

**Не собираем:** MAC-адрес, disk serial, IMEI.

### Хранение

- Сырые сигналы — только на клиенте (для пересчёта hash).
- На сервере и в Центре — `device_hash` (хэш нормализованного набора + соль инсталляции).

---

## Типы связей

| Тип | Источник | Вес | Смысл |
|-----|----------|-----|-------|
| `same_device` | `device_hash` | Высокий | Аккаунты с одного устройства |
| `shared_contact` | `contact.added` | Средний | Пересечение контактов |
| `communicates_with` | `message.sent` | Средний | Факт переписки |

## Политика платформы (целевая, фаза 2)

> Один человек — один аккаунт.

В MVP политика **не enforcement'ится** — только визуализируется через граф. Планируемые шаги:

1. Кластеризация связанных аккаунтов
2. Пороговые правила по весам рёбер
3. Ограничение регистрации в кластере
4. Бан кластера и защита от обхода по `device_hash`

---

## Desktop (fingerprint)

`desktop/internal/fingerprint`:

- Сбор сигналов устройства
- Вычисление `device_hash`
- Передача hash в Chat API при регистрации и входе

## Задачи реализации

1. Бинарник `security-center` с gRPC `IngestEvent`.
2. Схема БД: узлы (аккаунты), рёбра (связи), события (audit).
3. Логика создания/обновления рёбер по событиям.
4. Admin API + простой UI (таблица связей).
5. Fingerprint на desktop.
